# ПиРМИиКС Практическая работа 1

## Практические работы

- ПР1: UDP MOVEMENT/SHOOT, исходники в корне репозитория.
- [ПР2: измерение RTT, SRTT, джиттера и потерь](PR2/README.md): исходники, тесты и документация в `PR2/`.

Вторая практика добавлена последующими коммитами в тот же репозиторий. Первая практика сохранена.

Рабочая реализация задания «Разработка UDP-протокола и проектирование архитектуры» на C# и .NET 8.

## Архивная версия v1.0.0

- [Исходники и документация](archives/PR1_UdpBasics_SOURCE_v1.0.0.zip).
- [Готовая демонстрация для Windows 10/11 x64](archives/PR1_UdpBasics_DEMO_WIN10_x64.zip).
- [Описание архивов и контрольные суммы SHA-256](archives/README.md).

Исходный архив - фиксированный снимок, который не обновляется при каждом коммите. Готовая демонстрация взята из предоставленного комплекта; её побайтовое соответствие текущим исходникам не установлено.

Для демонстрации полностью распакуй ZIP, открой `RUN_SERVER.cmd`, затем `RUN_CLIENT_LOCAL.cmd`. Установка .NET для готового комплекта не требуется. Для двух компьютеров используй `RUN_CLIENT_LAN.cmd`, указав IPv4 сервера. Сервер слушает UDP-порт `7777` на всех IPv4-интерфейсах; в LAN разреши входящий трафик этого порта для частной сети. Остановка: `Ctrl+C`.

## Структура репозитория

```text
Client/       UDP-клиент
Server/       UDP-сервер
Protocol/     Пакеты и сериализация
docs/         Архитектура и спецификация протокола
demo_scripts/ Скрипты запуска готовых EXE
archives/     Архивные поставки
```

Исходники хранятся в Git как обычные файлы, а не только внутри ZIP. `bin/`, `obj/` и настройки IDE исключены. Скрипты в `demo_scripts/` предназначены для готовых `Server/Server.exe` и `Client/Client.exe`; исходники запускаются командами ниже.

## Реализовано

- две консольные программы: UDP-сервер и UDP-клиент;
- двусторонний обмен через `UdpClient`;
- бинарный заголовок `PacketType`, `SequenceNumber` (`uint16`) и `PayloadSize`;
- бинарные payload без зависимости от выравнивания структур;
- `MOVEMENT` с координатами `float x, y, z`;
- `SHOOT` с `uint8 weaponId`;
- обновлённое состояние игрока в ответе сервера;
- журнал всех принятых команд;
- отправка команд раз в секунду и таймаут ответа;
- описание архитектуры и спецификация протокола.

## Запуск

Открой два терминала в папке проекта.

Для сборки нужен .NET SDK с поддержкой C# 12 / `net8.0`, для запуска - .NET Runtime 8. Visual Studio IDE не требуется. Проекты можно собрать и без поддержки формата `.slnx`:

```powershell
dotnet build Server/Server.csproj -c Release
dotnet build Client/Client.csproj -c Release
```

Сервер:

```powershell
dotnet run --project Server
```

Клиент:

```powershell
dotnet run --project Client
```

Клиент для сервера на другом компьютере:

```powershell
dotnet run --project Client -- 192.168.1.50 7777
```

dotnet build PR1_UdpBasics.slnx

## Поведение и ограничения

Каждая третья команда - `SHOOT` с `weaponId=2`; остальные - `MOVEMENT` с дельтой `(0.5, -0.1, 0.25)`. На свежем сервере первые два движения дают `(1.0, -0.2, 0.5)`, третий пакет увеличивает `shots` до 1.

- Сервер хранит одно общее состояние для всех клиентов; многопользовательская архитектура в документации является планом развития.
- Клиент делает секундную паузу после ответа или двухсекундного таймаута, поэтому интервал отправки не строго одна секунда.
- Клиент выводит номер ответа, но не проверяет соответствие запросу или адрес отправителя.
- Нет повторной отправки, устранения дублей и упорядочивания пакетов.
- Проверяются заголовок и длины payload; NaN/Infinity и игровые границы координат не проверяются.
- При неверной длине payload сервер пишет исключение в консоль без отправки ответа. Журнал автоматически в файл не сохраняется.
