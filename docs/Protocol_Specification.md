# Спецификация UDP протокола

Все многобайтовые целые числа и числа с плавающей точкой передаются в сетевом порядке байтов (`big-endian`). Один UDP-датаграмм содержит ровно один пакет.

## Заголовок пакета

| Смещение | Размер | Поле | Описание |
|---:|---:|---|---|
| 0 | 2 | `Magic` | Константа `0x4D50`, ASCII `MP` |
| 2 | 1 | `Version` | Версия протокола, сейчас `1` |
| 3 | 1 | `PacketType` | Тип команды или ответа |
| 4 | 2 | `SequenceNumber` | Беззнаковый 16-битный порядковый номер |
| 6 | 2 | `PayloadSize` | Беззнаковый 16-битный размер payload в байтах |

Полный размер заголовка — 8 байт. Пакет отклоняется, если сигнатура или версия неизвестны либо `PayloadSize` не совпадает с фактической длиной датаграммы.

## Типы пакетов

| Код | Имя | Направление | Payload |
|---:|---|---|---|
| 1 | `MOVEMENT` | клиент → сервер | три `float32`: `x`, `y`, `z`, 12 байт |
| 2 | `SHOOT` | клиент → сервер | `uint8 weaponId`, 1 байт |
| 100 | `STATE` | сервер → клиент | `float32 x`, `y`, `z` и `int32 shots`, 16 байт |
| 255 | `ERROR` | сервер → клиент | строка UTF-8 переменной длины |

## Пример MOVEMENT

Команда перемещения с `SequenceNumber = 1` и дельтой `(0.5, -0.1, 0.25)`:

```text
4D 50 | 01 | 01 | 00 01 | 00 0C | 3F 00 00 00 BD CC CC CD 3E 80 00 00
Magic   Ver  Type   Seq     Size   X=0.5       Y=-0.1      Z=0.25
```

## Правила обмена

1. Клиент увеличивает `SequenceNumber` для каждой команды.
2. Сервер возвращает ответ с номером принятой команды.
3. После `MOVEMENT` сервер изменяет координаты авторитетного состояния.
4. После `SHOOT` сервер увеличивает счётчик выстрелов и учитывает `weaponId` в журнале.
5. При некорректном заголовке или неизвестном типе сервер отвечает `ERROR`, если пакет позволяет сформировать ответ.
6. Клиент ожидает ответ две секунды; истечение времени показывает возможную потерю UDP-датаграммы.
