# Отчёт по измерению задержки

## Методика

Клиент создаёт PING с уникальным `sequenceNumber`, сохраняет отправку в ограниченном `inFlight` и измеряет `RTT = receive_client - send_client` через `Stopwatch`. Серверные метки используются только для диагностики. SRTT обновляется по формуле `0.875 * SRTT + 0.125 * RTT`; первый RTT инициализирует оценку.

Статусы: `received`, `timeout`, `late_response`, `duplicate_response`, `unknown_response`. Повторные передачи не выполняются.

## Метрики

Джиттер рассчитывается как среднее `|RTT_i - RTT_(i-1)|` по соседним успешным ответам. Потери рассчитываются как `timeouts / sent * 100%`. Исходные измерения находятся в [latency_samples.csv](latency_samples.csv).

## Воспроизводимость

Запуск и параметры зафиксированы в [Experiment_Config.md](Experiment_Config.md). Для полноценного отчёта по всем сериям нужно выполнить команды для каждой строки конфигурации; CSV не заполняется выдуманными сетевыми значениями. Тестовый набор проверяет сериализацию, повреждённые пакеты, RTT/SRTT, тайм-ауты, поздние, дублирующиеся и неизвестные ответы.

## Ограничения

Данные в текущем CSV являются локальным baseline-прогоном; искусственные режимы воспроизводятся серверными аргументами. Графики строятся из CSV после выполнения всех шести серий, например в Excel, LibreOffice или Python matplotlib.
