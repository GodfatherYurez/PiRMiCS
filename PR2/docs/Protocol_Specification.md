# Спецификация протокола ПР2 и расширение ПР3

ПР3 добавляет поле `requiresAck` к заголовку из ПР2. Текущая реализация кодирует его последним байтом заголовка и использует `protocolVersion = 2`. Пакеты PING/PONG ПР2 всегда передают `requiresAck = 0`; поведение телеметрии не меняется. Клиенты и серверы, собранные по исходникам до ПР3, используют версию 1 и несовместимы с версией 2.

Все многобайтовые значения передаются в сетевом порядке байтов (`big-endian`). Одна UDP-датаграмма содержит ровно один пакет.

## Заголовок версии 2

| Смещение | Размер | Поле | Описание |
|---:|---:|---|---|
| 0 | 2 | `Magic` | `0x4D50` |
| 2 | 1 | `packetType` | `MOVEMENT=1`, `SHOOT=2`, `ACK=3`, `PING=10`, `PONG=11` |
| 3 | 2 | `sequenceNumber` | Порядковый номер пакета |
| 5 | 2 | `payloadSize` | Размер payload в байтах |
| 7 | 2 | `protocolVersion` | `2` |
| 9 | 1 | `requiresAck` | `1` — требуется ACK, `0` — не требуется |

## Полезная нагрузка

| Тип | Payload | `requiresAck` |
|---|---|---:|
| `MOVEMENT` | три `float32` (`x`, `y`, `z`), 12 байт | `0` обычно; может быть `1` |
| `SHOOT` | `uint8 weaponId`, 1 байт | `1` для надёжной команды |
| `ACK` | `uint16 acknowledgedSequence`, 2 байта | `0` |
| `PING` | `uint64 clientSendTimeUs`, 8 байт | `0` |
| `PONG` | исходная метка клиента и две метки сервера, 24 байта | `0` |

Парсер проверяет длину заголовка, сигнатуру, тип, версию, флаг, точную длину датаграммы и размер payload до чтения полезных полей. ACK подтверждает тот же `sequenceNumber` и в заголовке, и в payload.
